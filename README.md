# 续页 · 学习断片续接器

## 多端版本进展

- 网页：登录后首次显示四步引导，之后可从“个人 → 设置 → 使用教程”查看完整说明；首页“总览”显示待续接、学习中、已完成及下一步。手机单栏，平板在 768dp 以上保留双栏。
- Windows：运行 [安装包](dist/XuYe-Setup-1.4.0.exe)，安装后从桌面或开始菜单打开“续页”。这是 Visual Studio 2022 C++ 编译的原生 WebView2 窗口，静态页面与 Python 服务一同安装；窗口内自动连接固定的本机端口 18461，无需打开浏览器或手动输入地址。安装器在缺少 WebView2 Runtime 时会联网安装它。打包版数据库与窗口资料位于当前用户的 `%LOCALAPPDATA%/XuYe/`，与开发版 `data/` 分开。用 `build-windows.ps1` 可重新生成安装包。
- Android 手机/平板：安装[正式签名 APK](dist/Android/XuYe-Phone-Tablet-1.4.apk)（Android 8.0 及以上）。APK 已包含网页界面，首次打开直接进入本机空间，无需电脑或端口；创建任务、学习、暂停、查看续接卡、材料、备份与恢复可离线使用。手机和平板分别保存自己的本机数据。录音会请求 Android 麦克风权限；导出备份会打开 Android 文件保存界面。桌面小组件使用官方 `AppWidgetProvider`，展示最近一次打开续页时的待续接数量和标题。需要重新构建时运行 `build-android.ps1`，或在 Android Studio 打开 `android/`。
- 当前源码中的跨设备入口只有两种：自行部署服务器后手动发送/接收任务，或导出完整 ZIP 到目标设备再导入。已有 1.4 安装包和 APK 尚未包含新版图表、自定义插件、个性化备份及 Markdown 手册；用户要求暂不编译，需获得确认后再更新成品；旧包上的“连接电脑”对应自建服务器的一种局域网部署形式。Android 本机空间与服务器账号空间独立，切换空间不会自动迁移任务。模型推理和语音转写仍需用户配置可用接口；APK 不含模型权重。
- Wear OS：[正式签名 APK](dist/Android/XuYe-WearOS-1.4.apk)是圆屏简化总览，使用安全边距和滚动容器。配对 Android 手机打开续页后，Google Play services Data Layer 传送待续接数量和标题。手表不传完整任务、附件或模型密钥，也不在手表上编辑任务；需要支持 Wear OS 和 Data Layer 的配对设备。

两个正式 APK 已由本机 Android SDK 35 和 JDK 17 编译，使用相同的团队发布签名；手机/平板正式包已在 Android 模拟器上安装并打开。先前 debug 包完成了离线创建任务、重启后读取、模拟模型接口和文件导出测试。手表包与桌面小组件尚未在对应设备验收。签名密钥在当前电脑的 `%LOCALAPPDATA%\XuYe\signing\`，密码由 Windows 当前账号保护。换电脑前运行 `android/export-signing-key.ps1 -DestinationDirectory 你的私密备份目录`，自行设置并记住备份密码，妥善保管导出的 P12 文件。不要把密钥和密码提交到代码仓库。

如果设备上已安装上一版 debug APK，由于签名不同，不能直接覆盖安装正式包：先在旧版导出完整 ZIP，卸载 debug 包，安装正式包，再导入 ZIP。

记录学习中断时的位置、思路和下一步，使用续学卡在电脑、手机和平板上接着学习。

当前版本1.4：学习数据先保存在各设备本机的网页存储中，只有你选择任务并发送，其他设备才能接收。安装版 Android 自带独立本机空间；Windows 内嵌窗口也有自己的本机空间。原来在系统浏览器的学习数据不会自动进入新窗口，先在旧版导出 ZIP，再在安装版恢复。

## 第一次启动

需要Python 3.11及以上、Node.js 20.19及以上或22.12及以上（建议使用仍受支持的LTS版本）。

Windows双击根目录的 `start.cmd`。也可以在本目录打开终端：

```powershell
python run.py
```

初次运行需要联网安装依赖和构建界面，之后打开 http://127.0.0.1:8000 。点击“创建账号”，自行设置用户名与密码，没有预设公用账号。启动终端需要保持打开，Ctrl+C停止服务。

新版界面的动效使用 `motion` 运行依赖，固定版本记录在 `frontend/package.json` 和 `frontend/package-lock.json`。源码开发时在 `frontend/` 执行 `npm ci` 即可准备依赖；将来获得编译确认后，Windows 与 Android 构建脚本也会先执行 `npm ci`，再把前端产物连同 Motion 代码封入安装包或 APK，设备端无需另装 npm 包。当前已发布的安装包和 APK尚未包含新版总览、双路径数据页和完整教程。

重新准备依赖或重新构建：`python run.py --setup`；端口被其他程序占用时：`python run.py --port 8002`。

## 先试这条完整流程

1. 创建账号并登录，点击“新建任务”。填写目标、选择领域插件，可每行输入一个任务步骤。
2. 打开任务，点击“开始学习”。填写“当前做到哪里”“下一步最小行动”，其余内容按需补充。
3. 编辑约350毫秒后写入本机草稿；点击“保存本机草稿”保存到本机任务。此过程不上传到电脑网关。
4. 点击“保存并暂停”，会在本机新增快照，并结束这一次学习会话。没有AI也能查看模板续学卡；暂停不会自动同步到其他设备。
5. 进入“续学卡与AI”，点击“准备对话上下文”。复制后在连小理中实际对话，再粘贴真实回复。普通文本、JSON或JSON代码块都能导入。
6. 检查AI候选卡，修改后确认。AI原文、候选卡、确认版本和快照分别保留。
7. 下次点击“继续学习”。完成第一个有效行动后可“记录首个有效进展”，时间线会标明由用户确认的耗时。
8. 完成全部任务后“标记任务完成”，或归档。开始前可重新打开已完成的任务。

测试或演示中自行输入的示例不能当作实际应用效果，也不能把HTTP模型回复冒充连小理回复。

## 多设备使用

**方法一：自建服务器。**按[自建服务器部署说明](docs/self-host-server.md)运行续页服务，各设备打开同一地址、登录同一账号，在“个人 → 设置 → 数据与同步 → 自建服务器”中主动发送/接收任务。局域网内可以用已发布 Windows 版的“续页（局域网共享）”入口；跨公网应部署 HTTPS 服务。Android 内置本机空间切到服务器空间后，原任务不会自动出现，首次迁移可使用下面的 ZIP 方法。

**方法二：完整 ZIP。**在原设备的“数据与同步 → 完整 ZIP”中导出，再将所有 ZIP 分卷带到目标设备逐个导入。导入会创建任务副本，不覆盖已有任务，并恢复外观、字体文件、自定义插件和不含密钥的模型配置。多分卷请从 part-1 开始逐个导入。无需服务器即可完成迁移。

各设备有独立的本机任务库，服务器不可达时仍可创建、开始、暂停任务、上传本机材料及手动导入 AI 回复。服务器方式传递所选任务、断点、材料、AI 交互及其自定义插件定义，不传模型设置与密钥。普通 HTTP 局域网通常不能安装完整离线 PWA；需 HTTPS 或 localhost 及已经缓存的界面。清理站点或应用数据会删除本机记录，建议保留 ZIP 备份。

两台设备都改过同一任务时，发送会拒绝覆盖旧基准。接收前自动保存本机脏记录为独立副本，原文、附件和来源关系保留；你可比较并继续使用其中一份。接收的旧会话成为历史，新设备重新开始本机会话。网关逐版本保留已经同步的任务数据。跨网络使用需自行部署可信HTTPS网关，当前没有发布云端服务。

## 插件与材料

预设方案：通用学习、数学推导、编程排障、阅读理解、写作构思。用户可在「个人 → 设置 → 领域插件」自行添加专门字段和续学提示。插件是声明式配置，不执行脚本。

用户自定义插件直接在设置页创建，不需要改代码。开发者如需增加内置预设，可同步更新 `backend/app/plugins.py` 和 `frontend/src/local/plugins.mjs`。自定义插件只包含 `name / description / fields / warmup`，不会把用户输入当成 Python 或命令执行。

材料首先保存为当前浏览器中的文件，单文件最多10MB；下载从本机读取。选择同步任务时，附件一同传递；单任务同步附件合计上限30MB、完整请求50MB。更换设备不依赖原电脑磁盘路径。第一版不自动读取其他软件，也不自动解析PDF、运行代码或判断数学证明正确。

## 备份、恢复与离线

在“个人 → 设置 → 数据与同步 → 完整 ZIP”中导出或导入。新版 ZIP 包含当前账号任务、快照、材料、AI 交互、外观、字体文件、自定义插件、模型接口配置和语音配置（不含密钥）；导入生成新任务副本，已有任务不受覆盖。旧版的 Markdown/JSON 导出代码仍保留用于兼容，但新版数据页只把完整 ZIP 呈现为跨设备文件迁移方式。

学习数据正式保存在当前站点、当前账号的 IndexedDB 中，不能仅靠复制电脑的 `data/` 目录备份。`data/study.db` 保留账号、旧版记录及你明确发送的同步版本；`data/.model-key` 用于本机模型密钥封装。旧数据库不会自动删除。当前设备导出的完整 ZIP 包含尚未同步的学习任务，导出时也包含正在编辑的本机草稿；大备份按任务分卷，单个任务备份需小于 48MB。导入先验证附件 SHA256 和来源引用，再创建新任务副本。

网页在HTTPS或localhost环境下会注册service worker，缓存界面；每次成功打开工作台也会缓存该任务。之后断网可查看已缓存内容并保存本机草稿。首次未加载的页面或附件仍需联网。普通HTTP局域网可用网页核心功能，但通常不能使用service worker和完整PWA安装体验。

PWA的安装入口因系统与浏览器不同而异。退出登录后不会再自动进入离线空间；本机缓存按账号分开。恢复联网后，打开应用并处理待提交记录。本机数据库不是云备份，清理浏览器数据会清除本机任务。

## 个人与设置（当前源码）

主菜单为“总览”“学习任务”“学习分析”“已完成与归档”“个人”。分析页的图表来自本机真实会话、断点、任务状态及步骤，可点开日期明细。“个人 → 账号信息”显示当前用户名、账号ID、任务统计及退出登录入口；“个人 → 设置”包含以下页面：

- **模型与API**：添加多套配置，填写名称、完整请求地址、模型ID、可选密钥及超时。保存后在“默认AI方式”中选用。编辑时密钥留空保留原值，勾选“清除已保存的密钥”才移除。测试连接会发一条简短请求，可能计费。
- 在此页的**语音记录配置**中设置音频识别服务，以及从已有文本模型中选择整理模型。
- **外观设置**：浅色、深色、跟随系统、暖纸、深海夜读；六种强调色；100%–130%字号、布局密度、宋体/楷体/黑体及自定义字体文件。修改立即应用，按账号保存，离线打开时先读取本机外观缓存。
- **领域插件**：自行添加最多12个专门文本字段，插件定义随完整 ZIP 或关联任务同步。
- **数据与同步**：只呈现“自建服务器手动同步”和“完整 ZIP 导出/导入”两种跨设备方式；插件管理在独立页面。
- **使用教程**：从 `frontend/src/settings/guide.md` 加载完整 Markdown 手册，应用内可逐章阅读并下载。
- **关于我们**：展示硅基觉醒（Silicon Awakening）团队、队长张尚臻、队员庞博轩和马明泽、大连理工大学，以及应用版本号。页面只呈现团队自行提供的身份信息，不显示任何审核、认证或获奖状态。

模型配置保存在当前设备；密钥先由当前网关封装为绑定账号的密文，再保存在本机数据库中，不包含在 ZIP 或同步包里；可迁移的模型接口配置会进入 ZIP。`data/.model-key`是读取密文所需的本机文件，请与服务器数据库一起妥善保留；密钥不回显到浏览器。正式生成使用请求开始时选定的本机配置，之后切换默认项不会改变已发出的请求。换网关或丢失加密主密钥后，需要重新填写API密钥。

## 用语音填写中断记录

1. 在“个人 → 设置 → 模型与API”先添加一个文本模型。在“语音记录配置”中填写语音识别的完整端点、模型、密钥、语言（`zh`为中文，留空自动识别）及超时，启用音频转写API并保存。
2. 选择“语音整理模型”：可以单独选一个已有模型，也可跟随当前默认AI模型。连小理手动模式不能自动整理，使用该模式时需另选一个整理模型。
3. 学习工作台中点击“用语音整理中断记录”，录音或上传音频，再点“转写音频”。录音最多3分钟，上传文件最多20MB。支持wav、mp3、m4a、mp4、webm、ogg、flac、mpeg、mpga扩展名，实际格式还需被识别服务支持。
4. 检查和修改转写文本，点击“AI整理为表单”。逐项检查建议，可修改文本、取消不需要的字段。默认追加到已有内容；取消“追加到已有内容”表示明确替换选中的文本框。
5. 点击“填入选中字段”，回到工作台继续修改，然后用“保存并暂停”生成中断快照。语音整理不会更改任务状态、暂停原因或步骤完成勾选。

尚未配置时，可在语音弹窗里直接打开“配置识别与整理模型”。未填入的录音、转写及预览保存在当前设备的语音暂存中，关闭后再次打开可恢复。它们尚不是任务快照，不默认进入任务同步/学习备份；需要备份或同步的文本请先填入草稿，音频可作为任务材料保存。

音频识别接口使用multipart协议：`file`、`model`、可选`language`及`response_format=json`，响应读取`text`。文本整理复用Chat Completions协议。原始音频不作为学习附件永久保存；转写和整理在点击对应按钮后才发给配置的服务，可能产生服务商费用。语音密钥与模型密钥一样加密保存、不回显且不进入学习备份。

网页麦克风通常需要 HTTPS 或本机 localhost，普通 HTTP 局域网可上传手机录音；也可直接粘贴或使用输入法语音输入转写文本，只调用文本整理模型。安装版 Android 的内嵌页面使用安全来源并请求系统录音权限；模拟器没有可用录音输入设备，因此尚未在真实手机麦克风和真实供应商上完成验证。

## 本地模型接口

在“个人 → 设置 → 模型与API → 添加模型”选择Ollama或LM Studio预设：

- Ollama：`http://localhost:11434/v1/chat/completions`。
- LM Studio：`http://localhost:1234/v1/chat/completions`。

在电脑上自行启动对应服务并准备模型，填写模型 ID（无鉴权时密钥可空），保存后编辑配置可“读取可用模型”。点击“测试连接”，再设为当前模型。网页和 Windows 版的地址从运行 Python 网关的电脑解释；安装版 Android 本机空间直接从手机连接模型地址，手机上的 localhost 指手机，电脑模型需填写电脑的局域网地址并允许该服务被手机访问。程序不自动安装软件或下载模型，也不自动开放本地模型端口。本地模型仅指你配置的模型运行位置；使用服务商的云端模型仍会外发本次输入。语音识别使用独立的转写接口，可填写本地转写服务的兼容地址。

兼容协议见[Ollama文档](https://docs.ollama.com/api/openai-compatibility)和[LM Studio文档](https://lmstudio.ai/docs/developer/openai-compat)。

## 可选HTTP AI适配器

推荐在本机设置界面直接配置；旧版环境配置会在首次迁移时复制为本机模型配置。也可以复制 `.env.example` 为 `.env`，设置完整的 `AI_API_URL`、`AI_API_KEY`、`AI_MODEL`，重启后作为“服务器默认”选项使用。该适配器发送：

```json
{"model":"你配置的模型","messages":[{"role":"user","content":"本次任务及中断上下文"}]}
```

读取响应中的 `choices[0].message.content`。超时（默认30秒，可在界面设置为5–120秒）或响应不符合协议时，会记录失败，并保留原始学习信息；可继续使用手动导入。可在 `backend/app/model_client.py` 增加其他服务的协议适配器。真实供应商接口需要你提供配置后验证；当前不能保证任意供应商都接受这一协议。

`.env`已被Git忽略，密钥不会发送到前端。部署HTTPS时设置 `COOKIE_SECURE=true`。若使用代理，应保留原始Host；额外可信来源使用 `ALLOWED_ORIGINS=host:port` 配置。
