# 自建服务器同步：部署与使用

续页只提供两种跨设备数据方式：**自建服务器手动同步**和**完整 ZIP 导出/导入**。本文件说明第一种。服务器由使用者自行部署、维护和备份；项目没有公共云账号或自动同步服务。

## 它怎样工作

1. 每台设备的学习任务先写入自己的 IndexedDB。
2. 用户在“个人 → 设置 → 数据与同步 → 自建服务器”选中任务，点击“发送所选”。服务端把完整任务版本存入 SQLite。
3. 另一台设备打开**同一服务器地址**、登录**同一账号**，点击“获取服务器任务”，选中后“接收所选”。
4. 服务端比较任务版本：旧版本不能覆盖新版本。接收前如有本机改动，程序先保存一份独立副本。

服务器不会主动扫描设备、自动上传草稿，也不会把模型配置和 API 密钥装进任务同步包。电脑、浏览器和 Android 内置本机空间使用不同的网页存储区域；仅登录同一账号不等于已经迁移数据。

## 准备服务器

需要 Python 3.11+、Node.js 与 npm，以及可持久保存的磁盘目录。初次部署时，把完整项目源码放到你控制的服务器。`frontend/dist` 必须包含与你部署的源码相匹配的界面；正式构建命令请在本项目获得编译确认后再执行。部署完成后，请使用 Python 虚拟环境安装 `requirements.lock.txt` 中的依赖，并启动 `backend.app.main:create_app` 的 Uvicorn 工厂入口。

示例（Linux，假设已在项目根目录）：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
export STUDY_DATA_DIR=/srv/xuye-data
export COOKIE_SECURE=true
.venv/bin/python -m uvicorn backend.app.main:create_app --factory --host 127.0.0.1 --port 8000
```

Windows 服务器可将 `.venv/bin/python` 换成 `.venv\Scripts\python.exe`，环境变量按 PowerShell 语法设置。使用服务管理器保持进程运行；不要把服务的进程窗口关闭后还期望设备能同步。`STUDY_DATA_DIR` 目录必须可写，并在重启后保留。

跨公网使用时，在服务器前配置 HTTPS 反向代理，将请求转发到本机 `127.0.0.1:8000`，并保留原始 `Host` 请求头。浏览器与 API 应从同一个 HTTPS 域名访问。启用 `COOKIE_SECURE=true`，不要把无加密的 HTTP 服务直接暴露到公网。若使用不同来源，请在部署前确认并配置 `ALLOWED_ORIGINS`；默认同源方式最简单。

服务器需要备份 `STUDY_DATA_DIR` 下的 SQLite 数据库和 `.model-key`。数据库保存账号和已发送的同步版本；密钥文件用于旧配置或模型密钥的读取。用户的**尚未发送**的任务仍只在原设备，所以各设备还应定期导出完整 ZIP。

## 连接各设备

- **网页 / Windows：**在设备上打开同一续页服务地址，并登录同一服务器账号。Windows 安装版自带本机服务；如需让它充当其他设备的服务器，需使用其“局域网共享”启动入口。跨公网部署建议使用独立服务器和 HTTPS 地址。
- **Android 手机 / 平板：**APK 顶部点“连接服务器”，输入完整 `https://...` 地址，再登录服务器账号。也可以继续使用 APK 的“本机”空间离线记录。两个空间独立。
- **Android 本机空间已有任务：**先在该空间导出完整 ZIP，然后切到服务器空间导入；之后可在服务器空间主动发送任务。连接服务器本身不会复制本机空间的 IndexedDB。
- **Wear OS：**只接收配对手机的简短总览，不作为完整任务同步客户端。

如果不打算维护服务器，在每台设备的“完整 ZIP”页导出和导入即可。ZIP 导入生成副本，不覆盖已有任务；多分卷备份需逐个导入。
