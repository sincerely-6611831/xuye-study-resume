# 学习断片续接器：设计与实现计划

> **实施状态（2026-10-23）：** 用户已明确授权正式制作第一版，代码与启动脚本已落地。实际实现决定与验证结果见 docs/implementation-progress.md 和 docs/验收记录.md。本文件保留设计依据，后续增强项不代表已经全部实机验证。

**Goal:** 保存学习中断时的位置、思路、尝试和下一步，在再次学习时帮助用户恢复上下文，并记录实际恢复结果。

**Architecture:** 响应式 Web 应用，预留PWA安装和离线草稿；电脑、手机和平板通过同一服务访问账号下的记录。服务端统一保存正式任务、会话和中断快照，设备保留本机草稿。插件提供领域字段和恢复策略，AI 经统一适配器生成可审阅的建议，原始快照不受 AI 成败影响。

**Tech Stack:** 建议 React + TypeScript 响应式前端、Python + FastAPI 后端、服务端SQLite数据库与持久化附件目录、浏览器IndexedDB草稿。PWA阶段增加manifest和service worker。技术选型是建议，可按开发者熟悉程度替换。

**Spec:** 本文件“产品规格”来自用户要求及后续多设备补充；用户已授权按该方向制作模块化第一版。

## 全局约束

- 用户后续已要求正式制作第一版，本地实现及验证已获授权；公网发布另行确定。
- 优先同一用户跨设备记录与恢复；支持统一网页入口和账号登录。多人协作、操作系统级采集后置。
- 原始事实、用户修改、AI建议分别保存，AI不得直接修改完成状态。
- 中断记录先持久化，再生成摘要。断网时只能保存本机草稿或待提交快照，恢复本机已缓存内容；服务端确认前不显示跨设备同步成功。
- 第一版插件是随应用发布的配置与可信内置逻辑，不支持安装任意第三方可执行代码。
- 连小理的程序化调用权限尚未确认。参赛基础路径为复制上下文至连小理、真实交互、粘贴导入结果；具备合法可用接口后再接入自动调用。

## 产品规格

### 1. 信息结构和界面

项目/课程 → 学习任务 → 学习会话 → 中断快照。

示例：高等数学 → 理解分部积分 → 今天第2次学习 → 在选择 u 和 dv 时暂停。

一个任务可以产生多次会话，每个会话可产生多个保存点；明确的暂停动作结束当前会话，下次继续建立新会话并引用恢复用的快照。

建议四个主页面：

1. 任务总览：标题、领域、状态、阶段、最近中断时间、下一步；支持课程、标签、状态筛选。
2. 学习工作台：当前材料、笔记、任务步骤、开始/暂停按钮、草稿保存提示。
3. 恢复面板：上次做到哪里、为何暂停、已试过什么、下一步、恢复问题与材料入口。
4. 历史与设置：快照时间线、版本差异、插件选择、AI连接、导出与备份。

第一版使用显式任务步骤，显示“完成3/5步”。数学理解等无明确总量的任务显示“探索中/已找到思路/待验证”，不由AI猜测百分比。

### 2. 三组独立分类

- 任务状态：todo、active、paused、blocked、done、archived。
- 中断原因：time_limit、external_interrupt、knowledge_gap、waiting_resource、fatigue、unknown。
- 领域类型：general、math、coding、reading、writing。

领域选择插件，中断原因决定恢复策略，两者不能混为一个类型。例如数学题既可能因时间不足暂停，也可能因概念不懂阻塞。

状态规则：开始将 todo/paused/blocked 任务转为 active；paused/blocked 恢复时记录原状态。中断转 paused 或 blocked；完成只由用户确认转 done；done 可明确重新打开。建议同时只保留一个 active 会话，切换任务时先保存原任务。无有效快照的任务可以直接开始，但不能伪造“上次思路”。

### 3. 快照需要保存什么

统一字段：目标、材料位置、当前步骤、已完成内容、当前思路、尝试及结果、障碍、下一步、中断原因、原始笔记、时间、插件及版本。

示例数据仅用于解释结构，不是参赛实测记录：

```json
{
  "schema_version": 1,
  "task_id": "task-example",
  "session_id": "session-example",
  "plugin_id": "math",
  "plugin_version": "1.0.0",
  "goal": "完成一道分部积分练习并说明选择依据",
  "position": {"resource_id": "resource-example", "locator": {"page": 12, "exercise": "3"}},
  "current_step": "确定u和dv",
  "completed": ["抄录题目", "列出分部积分公式"],
  "thought": "考虑令对数项为u，但没有验证剩余积分",
  "attempts": [{"action": "尝试另一种分配", "result": "计算变复杂"}],
  "blocker": "尚不确定分配依据",
  "next_action": "分别列出两种分配后的积分并比较",
  "reason": "knowledge_gap",
  "domain_data": {"verified_steps": [], "uncertain_steps": ["u和dv的选择"]}
}
```

三个填写层级：

- 快速中断：只填“做到哪”和“下一步”，其余字段可空；已有工作台内容自动带入。
- 完整中断：按领域表单补充思路、尝试、障碍。
- 异常退出：下次打开提示恢复最后一次已保存草稿，标记为“异常恢复候选”，由用户补全和确认。

保存方式：编辑停止约1秒后先把草稿写入本机IndexedDB，再在联网时提交后端；明确点击暂停时立即提交快照，等待服务端确认。界面区分“已保存本机”“待同步”“已同步”和“存在冲突”。后端成功后才清除对应待提交项。断网时保留待提交快照，重新打开应用或恢复联网时重试；不依赖浏览器关闭后的后台同步。不能承诺取回尚未保存的内容，也不能在另一设备读取仍只保存在本机的数据。

### 4. 恢复流程

选择任务 → 读取最近确认快照 → 展示原始状态 → 检查材料是否变化 → 生成或读取续学卡 → 用户选择直接继续/先回顾/补充信息 → 开始新会话 → 记录首个有效进展。

续学卡结构：事实摘要、未解决问题、一个最小下一步、一道可选热身问题、材料入口、待确认信息。事实摘要引用快照字段或材料ID；建议与事实在界面上分别标识。

用户无需通过测试才能继续。热身回答错误或自述忘记时，提供短回顾；恢复问题只是帮助回忆，不作为掌握程度的可靠测量。

记录打开恢复面板、开始会话、用户标记“已重新进入状态/完成第一步”的时间。界面可显示恢复耗时，但注明结束点由用户确认；页面停留时间不能自动当作恢复时间。

### 5. AI接入方式

统一业务接口的概念签名：

```text
prepare_context(checkpoint_id, purpose) -> ContextBundle
submit_ai_job(context_bundle, provider_id) -> AIJob
import_ai_result(job_id, raw_text) -> DraftResult
accept_draft(draft_id, edits) -> ResumeCardVersion
```

ContextBundle 包含任务目标、当前快照、必要的历史差异、用户选取的材料片段、插件输出要求和来源ID。默认不发送全部历史；长材料按用户选择章节截取，并注明哪些上下文未包含。

三个适配器：

- manual_lianxiaoli：导出上下文和提示词，用户在连小理完成真实交互，再导入回复；若JSON无效保留原文，允许字段映射或手动整理。
- http_provider：后端保存服务配置并调用供应商正式接口；密钥不下发前端；根据实际接口实现独立适配器。
- template_fallback：不调用模型，直接把快照字段排成续学卡；AI不可用时立即可用。

AI接入点：中断时整理零散笔记；恢复时生成摘要和最小行动；遇到知识障碍时生成解释/追问；任务结束时总结实际有效的方法。

AI结果有 draft、accepted、rejected 状态。原始快照不可被覆盖；用户修订产生新版本。每个请求记录 provider、模型标识（可获得时）、提示词版本、输入快照ID、原始回复、耗时、错误。手动导入明确标记 manual_import，不冒充API调用。

异步任务以SQLite记录状态 pending/running/succeeded/failed/cancelled/awaiting_user/interrupted；小规模由本地后台执行器处理。接口请求设可配置超时，初始建议30秒；失败显示原因并提供重试，应用重启后将遗留 running 标记 interrupted 并允许显式重试。回传时核对输入快照版本，旧回复标记过期候选，不覆盖用户新编辑。

JSON校验只检查结构、字段类型、来源ID是否存在，不能证明内容事实正确；关键学科内容仍需材料或人工核对。

### 6. 插件机制

插件定义“该问哪些问题、保存什么状态、怎样恢复”，AI服务负责“调用哪个模型”。同一个AI适配器可被多个插件使用。

第一版采用内置插件注册表：

```text
PluginManifest:
  id, name, version, supported_schema_versions,
  capture_schema, resume_sections, prompt_templates

validate_domain_data(data) -> ValidationResult
build_context(checkpoint) -> DomainContext
fallback_card(checkpoint) -> ResumeCard
```

capture_schema 描述表单字段、必填项、类型和帮助文字；前端统一表单组件渲染。插件使用统一的快照基础字段，只把差异存入 domain_data。插件配置有版本，旧快照按旧版本读取或经显式迁移转换，不能静默按新结构解释。插件禁用后仍能显示通用字段和原始领域数据。

| 插件 | 额外记录 | 恢复方法 | 首版边界 |
|---|---|---|---|
| 通用 | 当前行动、障碍、下一步 | 原样回放，再给一个最小行动 | 必做 |
| 数学 | 题目、条件、已验证推导、存疑步骤 | 从最后一个确认步骤继续，提示检查适用条件 | 不自动认定证明正确 |
| 编程 | 目标行为、代码片段、报错原文、环境说明、试过的修复 | 重现问题说明，提出下一条诊断步骤 | 手动粘贴材料，不执行代码或修复命令 |
| 阅读 | 材料ID、页码/章节、中心论点、未解术语 | 回顾论证位置，提出接下来阅读的问题 | 首版文本片段与手填位置，PDF解析后置 |
| 写作 | 大纲、当前段落、核心论点、待补证据 | 找回该段写作意图，列出下一段目标 | AI补写作为候选，引用不得编造 |

推荐先实现通用和数学两个插件，验证接口可扩展，再加入其他领域。新增领域通常只需配置表单和提示词；需要计算或文件解析时，再增加可信内置处理器。

### 7. 多设备访问、同步与PWA

本节依据用户提出的多设备兼容需求修订；“同一用户跨设备共享进度”作为建议范围明确纳入设计。

**部署选择：**

- 开发时在电脑本地运行，localhost只指当前访问设备，手机访问自己的localhost不会访问到电脑。
- 局域网演示时，电脑运行前后端，其他设备通过电脑的局域网地址访问同一服务；要求网络允许设备互通，电脑保持运行。普通HTTP局域网网页可演示核心流程，但不能据此承诺完整PWA安装/离线能力。
- 正式多设备使用时，前后端部署到统一可访问的HTTPS地址，服务端持久保存数据库与附件；电脑关闭后手机仍可通过该服务继续学习。当前只制定方案，不实际部署或购买服务。

**设备适配：**

- 用CSS Grid/Flex和媒体查询处理屏幕宽度。初始布局建议：窄屏小于768px单栏；中屏768—1199px双栏；宽屏1200px及以上可三栏，最终按内容调整。
- 手机优先快速记录、查看续学卡、继续学习；电脑提供材料、笔记、AI建议并排查看；平板支持横竖屏切换。
- 所有关键操作可点按，不依赖悬停；表单适应软键盘。代码和长公式仅在各自区域横向滚动。
- 核心依赖标准表单、文本、文件上传、普通HTTP请求；不以浏览器专有文件系统接口、推送或语音识别作为必需能力。

**统一数据与账号：**

- 账号对应任务、快照和材料；会话登录由后端验证，浏览器持有会话cookie。个人演示可预设一个账号，仍需验证每个资源属于该账号。
- SQLite位于一台服务端的持久化磁盘，不把数据库文件分发到每台设备做文件同步。各设备访问同一API获取正式版本。
- 应用打开、页面回到前台、用户点击刷新时获取最新任务和快照；第一版采用请求刷新即可，不要求实时协同或WebSocket。
- 同一用户默认只允许一个活动学习会话；手机接续时如电脑会话尚未结束，展示状态并由用户选择接管或取消。接管时结束旧会话并创建新会话，旧设备的后续写入返回状态冲突。
- 草稿与状态修改携带expected_revision；服务端版本不一致时返回409。保留本机草稿与服务端版本，由用户选择内容；不采用最后写入直接覆盖。
- 明确的暂停动作携带request_id并在服务端按账号去重。离线待提交项只在服务端接受后成为正式快照；发生会话冲突时保留为恢复候选，不能回滚新设备正在进行的任务状态。

**附件与插件：**

- 文件由设备选择并上传，返回resource_id。快照引用resource_id和页码/题号等位置，不依赖D盘路径。其他设备通过有账号校验的接口下载或预览材料。
- 小规模单实例可沿用服务端持久化附件目录；多实例部署前再引入共享文件或对象存储。
- 领域插件由服务端维护版本和schema；所有设备获取同一配置，计算和AI调用在服务端运行，客户端只负责显示与交互。

**PWA增强：**

- 响应式网页已能解决核心跨设备访问；PWA额外提供支持环境下的桌面/主屏入口和离线体验，不能自动解决数据同步。
- 增加manifest，包含名称、图标、start_url、display等。正式环境使用HTTPS，安装入口随浏览器/系统不同而变化；不能安装时继续使用网页。
- 后续用service worker缓存应用界面，IndexedDB缓存最近续学卡和本机草稿，按账号隔离；离线只展示已缓存材料与记录，首次未加载设备仍需联网。
- 断网期间不调用云端AI；重连且应用打开时提交待处理内容并拉取新版本。上传前展示所选材料，不默认缓存全部附件或聊天历史。

## 数据表与接口

| 数据表 | 核心字段与关系 |
|---|---|
| users | id、login_name、password_hash、created_at |
| auth_sessions | id、user_id、token_hash、expires_at；与学习会话sessions区分 |
| tasks | id、user_id、title、course、domain、plugin_id、status、stage、revision |
| task_steps | id、task_id、title、status、sort_order |
| sessions | id、task_id、source_checkpoint_id、started_at、ended_at、end_reason |
| drafts | task_id、session_id、device_id、revision、payload、saved_at |
| checkpoints | id、task_id、session_id、schema_version、plugin_id/version、payload、created_at |
| resources | id、user_id、managed_path、original_name、content_hash |
| checkpoint_resources | checkpoint_id、resource_id、locator_json |
| ai_jobs | id、checkpoint_id、purpose、provider、status、input、raw_output、error、prompt_version |
| resume_cards | id、checkpoint_id、ai_job_id、revision、content、status |
| recovery_events | id、session_id、checkpoint_id、event_type、timestamp |
| request_receipts | user_id、request_id、action、result_id；用于明确动作去重 |

重要写入使用数据库事务。一次暂停应原子完成：插入快照、结束会话、更新任务状态、记录去重结果。客户端为动作携带 request_id，重复请求复用结果，避免双击产生重复快照。草稿更新携带 expected_revision，版本不一致时返回冲突并保留两个版本供用户处理。所有接口从服务端登录会话获取user_id；任务子记录通过所属任务校验账号，不能只相信请求传来的ID。device_id只用于记录来源，不作为登录凭据。

接口边界建议：

- POST /auth/login、POST /auth/logout、GET /auth/me：建立/退出会话和读取当前账号。
- POST /tasks：创建任务。
- POST /tasks/{id}/start：开始或恢复，检查是否已有活动会话。
- PUT /tasks/{id}/draft：更新草稿，携带 expected_revision。
- POST /tasks/{id}/pause：保存快照并切换状态，携带 request_id。
- GET /tasks/{id}/checkpoints：时间线。
- GET /checkpoints/{id}/resume：读取现有续学卡，缺少时返回模板卡。
- POST /checkpoints/{id}/ai-jobs：创建生成请求或手动导出任务。
- POST /ai-jobs/{id}/import：导入人工交互结果。
- POST /resume-cards/{id}/accept：确认或修改AI候选卡。
- POST /sessions/{id}/recovery-events：记录开始恢复、首个有效进展等事件。
- GET /plugins：插件字段与能力列表。
- POST /resources、GET /resources/{id}：上传和按账号权限下载/预览材料。
- POST /exports：导出选定任务和真实过程材料。

后端用FastAPI定义请求结构和接口；其类型验证与自动接口文档适合核对模块契约。数据库初期按标题、课程、标签、正文子串搜索；数据增多后可评估SQLite FTS5，中文检索需额外验证分词或trigram对短词的效果，不默认英文分词器能满足中文需求。

## 实施顺序与验收

### 第一阶段：任务与手动快照闭环

- [ ] 建立数据库迁移、账号与登录会话、任务/步骤/学习会话结构、响应式任务列表和工作台。
- [ ] 实现通用中断表单、事务保存、幂等暂停、草稿版本检查。
- [ ] 实现纯模板恢复面板和从快照新建会话。
- [ ] 验证：电脑新建任务→记录→暂停→手机刷新→恢复，同一账号记录一致；双击暂停只有一条快照；两个任务不混用；另一个账号不能读取该记录。

产出：即使没有模型，也能跨设备实际记录并找回已同步的中断状态。

### 第二阶段：领域插件

- [ ] 固定插件manifest与domain_data契约，开发统一字段渲染器。
- [ ] 实现数学插件和通用降级读取。
- [ ] 验证：同一个工作台能切换两类任务表单；旧版快照可读；禁用插件后原始记录仍可访问。

产出：证明专门领域支持可以通过插件扩展，页面不必复制一套。

### 第三阶段：连小理辅助恢复

- [ ] 实现上下文导出、真实回复导入、原始回复留存和用户确认。
- [ ] 添加字段与来源ID校验，失败时保留原文并提供手动整理。
- [ ] 按条件加入正式API适配器，记录超时、失败和旧版本回复。
- [ ] 验证：断网可保存本机待提交记录并查看当前已加载信息，界面不误报已同步；导入非法JSON不丢原文；AI回复晚于用户修改时不会覆盖最新状态；未知来源ID被标记。

产出：基于真实快照生成可追溯的续学卡，具有真实连小理交互证据。

### 第四阶段：参赛展示与观察

- [ ] 增加快照时间线、阶段变化、恢复事件和Markdown/JSON导出。
- [ ] 用两次实际中断完成同一个小任务，保留原始材料、真实交互和恢复后的实际成果。
- [ ] 记录恢复所需时间及用户主观回忆负担；若做对照，使用难度相近任务并说明顺序和样本局限。
- [ ] 验证：导出材料可追溯到快照和真实回复；备份含附件且能恢复；电脑暂停→手机继续的演示使用真实记录；同账号跨设备冲突保留两个版本；图文/视频只使用实际发生的过程。

产出：可用于讲述“中断前—记录—连小理辅助—恢复—完成”的完整案例。

### 第五阶段：PWA与离线增强

- [ ] 增加manifest、应用图标和适用设备的安装指引；正式服务使用HTTPS。
- [ ] 增加应用界面缓存、最近续学卡缓存和断网后重开应用的恢复入口。
- [ ] 验证：支持环境能从主屏启动，不支持安装环境仍可用网页；缓存后断网重开能查看已缓存续学卡；本机待提交记录在重连后正确上传；冲突不静默覆盖。
- [ ] 至少在Windows的Chrome/Edge、iPhone/iPad的Safari、Android的Chrome中人工检查关键流程；覆盖约360px窄屏、平板横竖屏和桌面宽屏，记录实际测试系统与浏览器版本。

产出：安装体验和离线能力是经过单独验证的增强功能，不把网页能打开等同于全部平台能力一致。

## 重点检查的五类情况

1. 网络失败或AI超时：第一阶段保证原始记录，第三阶段验证模板恢复。
2. 异常退出与未保存输入：第一阶段恢复最后已保存草稿，并明确保存时间。
3. 跨设备并发编辑、重复点击与迟到回复：第一阶段验证revision和request_id及账号归属，第三/四阶段验证过期回复和冲突处理。
4. 插件升级/禁用或材料变化：第二阶段保留旧数据，第四阶段验证材料指纹和备份恢复。
5. AI建议失实或无依据：第三阶段保留原文、来源和确认步骤；结构校验不等同事实验证。

## 可增加的亮点

- 低负担暂停：常用中断原因一键选，核心只填两句话，避免记录成本过高。
- 按中断原因恢复：时间不足直接续做；概念卡住先澄清前置知识；等待资料先检查资料是否到位。
- 历史尝试提示：恢复时显示“已经试过而无效的方法及当时结果”，减少重复绕路。
- 材料变化提示：导入新版本时比较指纹，提醒旧续学卡可能需要重新确认。
- 可携带续学卡：导出Markdown，应用不可用时仍能直接阅读；完整恢复用JSON加附件备份。
- 恢复模式选择：快速回顾与完整回顾由用户选，依据用户反馈逐步调整。

建议首个竞赛演示集中在数学或编程中的一个真实小任务；其他插件用于说明扩展方式，不能把未实现能力当作已完成成果。
